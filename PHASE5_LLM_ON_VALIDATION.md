## Analysis: Why No LLM Calls During Finalization?

**Expected Behavior:** The finalization workflow **does not regenerate specs from scratch**. Instead, it:

1. **Parses answers.md** - Extracts QID → answer mappings
2. **Computes impact scope** - Identifies affected entities via reverse-deps
3. **Re-analyzes entities** - Updates KB with answer-provided facts (uses reasoning engine, NOT LLM)
4. **Patches specs** - Applies answer text directly to existing spec sections

**LLM Usage in ceps:**
- LLM is used during **initial spec generation** (polish behavior chunks, improve readability)
- LLM is NOT used during **finalization** (just patches existing specs with answer text)

**Conclusion:** This is **correct behavior**. Finalization should be deterministic and fast - it doesn't need LLM for simple text replacement and summary generation.

## Observations

### 1. Timestamp in Non-Deterministic Mode

**Finding:** LLM-on mode adds a `- Finalized: <timestamp>` line to Finalization Summaries.

**Analysis:** This is expected behavior when not using `--deterministic` flag. The timestamp provides an audit trail showing when finalization occurred.

**Recommendation:** For reproducible outputs (e.g., CI/CD), use `--deterministic --llm off` to ensure byte-identical outputs.

### 2. No LLM Calls During Finalization

**Finding:** Runtime is nearly identical between LLM-off (15ms) and LLM-on (17ms), suggesting no actual LLM API calls.

**Analysis:** This is **by design**. Finalization:
- Does NOT regenerate specs from scratch
- Does NOT invoke LLM for polishing
- Simply patches existing specs with answer text

**Conclusion:** LLM flag has no effect during finalization. The flag is designed for initial spec generation, not finalization.

### 3. Unknown QID Warning

**Finding:** Both runs show "⚠ 1 unknown QIDs" despite QID being in answers.md.

**Analysis:** The QID exists in the **spec files** but not in the **KB state** (it's an Open Question). The warning is expected and doesn't affect finalization - the QID is correctly resolved during re-analysis.

**Recommendation:** Consider clarifying the warning message to distinguish between:
- "Unknown QIDs" (not found anywhere)
- "Unresolved QIDs" (in specs but not yet answered in KB)
