# Phase 2 Output Schema Analysis

**Purpose:** Document what Phase 2 actually provides vs. what Step 0 assumed

---

## What Phase 2 ACTUALLY Provides

### 1. Import Relations (`src/parser/fact-extractor.ts:160-169`)

```typescript
{
  subjectId: filePath,        // e.g., 'src/caller.ts' (NOT entity ID!)
  predicate: 'imports',
  objectId: moduleSpecifier,  // e.g., './utils' or 'express'
  source: { kind: 'ast', file: filePath }
  // NO details.imported field
  // NO named imports list
}
```

**Key Facts:**
- Import relations are **file-level**, not entity-level
- No information about WHAT is imported (named imports, default, etc.)
- Only the module specifier is stored

---

### 2. Call Relations (`src/parser/fact-extractor.ts:81-86, 149-154`)

```typescript
{
  subjectId: entityId,        // Content-based hash (e.g., 'k3F9xL2mP8')
  predicate: 'calls',
  objectId: calleeExpr,       // Raw text: 'helper()', 'service.create().save()'
  source: { kind: 'ast', file: filePath }
}
```

**Key Facts:**
- subjectId IS an entity ID (good!)
- objectId is raw expression text (as expected)
- No additional metadata about the call

---

### 3. Entity IDs (`src/kb/id-generation.ts:44-72`)

```typescript
// Generated by: generateAnchor(name, content, existingAnchors)
// Algorithm:
// 1. Normalize: slug + content → lowercase, collapse whitespace
// 2. Hash: SHA-256 of normalized text
// 3. Encode: Base62 (10 or 16 chars)
// Example: 'k3F9xL2mP8' or 'Q7nR4sT1vX8yZ2aB'
```

**Key Facts:**
- IDs are **content hashes**, NOT sequential
- Lexical sort order is **pseudo-random**, NOT source order
- No way to determine source order from ID alone
- No parent-child metadata (methods don't reference their class)

---

### 4. Entity Schema (`src/parser/fact-extractor.ts:35-47, 128-140`)

```typescript
{
  id: string,           // Content hash
  kind: EntityKind,     // 'function' | 'class' | 'method' | 'constant'
  name: string,
  path: string,         // File path
  signature?: string,
  exported?: boolean,
  visibility?: 'public' | 'internal',
  attributes?: { ... }
  // NO parentId field
  // NO sourcePosition field
}
```

**Key Facts:**
- Methods in same file as their class (path matches)
- No explicit parent reference
- No source position/line number

## What Step 0 ASSUMED (Incorrectly)

### Assumption 1: Import Relations Have Named Imports
```typescript
// ASSUMED:
{
  subjectId: entityId,  // ❌ Actually: filePath
  details: {
    imported: ['helper', 'render']  // ❌ This field doesn't exist
  }
}
```

### Assumption 2: Entity IDs Sort by Source Order
```typescript
// ASSUMED:
const sorted = entities.sort((a, b) => a.id.localeCompare(b.id));
// sorted[0] is first in source ❌
// sorted[1] is second in source ❌
```

**Reality:** Hash order is random. Test passed because I used:
- `'class-first-abc123'` (sorts before)
- `'class-second-def456'` (sorts after)

But real hashes like `'k3F9xL2mP8'` and `'A1bC2dE3fG'` could sort in any order.

## Implications for Step 0

### Issue 1: Import-Based Disambiguation CANNOT Work

**Current Code:**
```typescript
// src/reasoning/relation-resolver.ts:127-148
buildImportMap(relations: Relation[]): Map<string, Map<string, string>> {
  for (const relation of relations) {
    if (relation.predicate === 'imports') {
      const callerId = relation.subjectId;  // ❌ This is a file path!
      // ...
      importMap.get(callerId)!.set(name, sourcePath);  // Never matches
    }
  }
}

// Later in resolveSimpleName:
const imports = this.importMap.get(callerId);  // callerId = entity ID
// ❌ Always undefined! Keys are file paths, lookup is by entity ID
```

**Fix Required:**
- Key importMap by **file path** (what Phase 2 provides)
- Lookup by **entity's file path** (entity.path)
- Accept that we don't know WHICH imports were used (all-or-nothing per file)

---

### Issue 2: Class/Method Matching CANNOT Use ID Sort

**Current Code:**
```typescript
// src/reasoning/relation-resolver.ts:263-270
const classesInFile = allEntities.filter(...)
  .sort((a, b) => a.id.localeCompare(b.id));  // ❌ Random hash order
const sortedMethods = methodsInFile.sort(...);  // ❌ Random hash order

// 2nd class might have smaller hash than 1st class!
```

**Fix Required:**
- Cannot determine source order from available data
- Need different strategy:
  - Option A: Match by **entity count heuristic** (Nth class → Nth method)
  - Option B: Accept limitation, fall back to first match
  - Option C: Request Phase 2 enhancement (add parentId field)

## Recommended Fixes for Step 0

### Fix 1: Import Map by File Path

```typescript
buildImportMap(relations: Relation[]): Map<string, Set<string>> {
  const map = new Map<string, Set<string>>();  // filePath → set of module specifiers

  for (const relation of relations) {
    if (relation.predicate === 'imports') {
      const filePath = relation.subjectId;  // This IS a file path
      const moduleSpec = relation.objectId || '';

      if (!map.has(filePath)) {
        map.set(filePath, new Set());
      }
      map.get(filePath)!.add(moduleSpec);
    }
  }
  return map;
}

// In resolveSimpleName:
const callerEntity = this.kb.getEntity(callerId);
const imports = this.importMap.get(callerEntity?.path);  // Lookup by file path
```

---

### Fix 2: Class/Method Matching Without Sort

**Option A - Accept Limitation:**
```typescript
// For same-named methods in multiple classes:
// Without source order or parent IDs, we cannot reliably distinguish them
// Fall back to first match with a clear comment about the limitation
```

**Option B - Count-Based Heuristic:**
```typescript
// Match by insertion order (entities array order from parser)
// Parser visits classes/methods in source order
// Use array index as proxy for source position
const classIndex = allEntities.findIndex(e => e.id === classEntity.id);
const methodIndex = methodsInFile.findIndex(id => id === methodId);
```

**Option C - Document as Phase 2 Enhancement:**
```typescript
// Add to Entity interface:
interface Entity {
  parentId?: string;  // For methods: ID of containing class
  // OR
  sourcePosition?: number;  // Line number or character offset
}
```

For Step 0, recommend **Option A** (accept limitation, document clearly).
